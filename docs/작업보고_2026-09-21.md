### 1-2. 오늘 확정된 결정
| 주제 | 결정 |
|---|---|
| 앱 방향 | 심플한 **공부 관리 웹앱**. 앱 내부 AI 기능 없음 |
| 개발 방식 | 코드는 Claude Code로 작성(운영 측 확인받음), 마지막에만 Genspark로 마무리·배포 |
| 기술 스택 | HTML/CSS/JS + Hono(TypeScript) + Cloudflare Pages. "파이썬만"에서 변경 (Genspark 호스팅이 파이썬 서버 미지원) |
| 데이터 저장 | Cloudflare D1 + 직접 구현 로그인 (Genspark 호스팅이 D1·R2 지원한다고 답변). 앱 코드는 저장소 루트에 둠 |
| 주요 기능 | 공부기록 타이머, To-do, 개인 캘린더, 주간 목표, 스터디, 레벨업 시스템 |
| 타이머 | 과목 선택 → 시작 → 일시정지/재개 → 종료 → 회고. 일시정지 시간은 공부시간에서 제외. 새로고침해도 유지. 동시에 1개 |
| 8시간 상한 | 기록 1건은 최대 8시간. 넘으면 자동 종료 + "한 번 끊고 점검한 뒤 다시 켜기" 안내. 일시정지에는 상한 없음 |
| 회고 | 4칸(공부한 내용 / 성과 / 어려웠던 점 / 비고), 전부 선택. 스터디에는 "공부한 내용"만 공유 |
| To-do | 단순 체크리스트. 캘린더 연동 없음, 공부 종류 태그 없음 |
| 스터디 | 취지 = 서로의 공부 현황을 보며 자극받는 공간. **모임 일정 기능 제외.** 기록에 **응원(👏)·댓글** 추가. 개인 기록은 가입한 모든 스터디에 자동 공유 |
| 화면 구조 | 하단 탭 5개(홈 / 기록 / 할 일 / 캘린더 / 스터디), 타이머는 홈에서 전체 화면 |
| 다크/라이트 | 기본 제공 |
| 디자인 통일 | **정합 단계에서 팀장이 지시** (그 전까지 임시 색 유지) |
| 역할 | 팀장 + Claude Code = 전체 코드·캘린더·스터디 / 팀원 1 = 캐릭터·로고 / 팀원 2 = 타이머·To-do 인터페이스 |

### 1-4. 확인한 것
- **자동 검증 55개 항목 모두 통과** (실제 서버에 계정 3개로 실행)
  - 일시정지 시간 제외, 종료 중복 클릭 시 기록 1건, 8시간 상한·방치 자동 종료
  - A·B 같은 스터디 / C 다른 스터디: 기록·응원·댓글이 섞이지 않음
  - 스터디 2곳에 공유돼도 개인 누적은 한 번만
  - 남의 할 일·일정·댓글에 접근하면 서버에서 거부
  - 기록을 지우면 합계·피드·경험치가 함께 바뀜
- **브라우저에서 직접 확인**: 가입 → 홈 → 타이머 전 과정(일시정지 상태에서 새로고침 포함) → 기록 → 할 일 → 캘린더 → 스터디(응원·댓글) → 다크 모드
- 타입 검사·빌드 통과
- 검증 중 찾아 고친 버그 3건: 일시정지 시간이 소수점으로 계산됨 / 멈춘 타이머 숫자가 1초씩 흔들림 / "공부 중" 표시 줄바꿈 깨짐

> 위 확인은 모두 **팀장 PC(로컬)** 기준이다. 실제 배포 환경(Genspark)에서는 아직 한 번도 실행해 보지 않았다.

## 4. 위험 요소

1. **배포 경로가 아직 검증되지 않았다.** Genspark의 답변(D1·R2 지원, GitHub 가져오기 가능)은 Genspark AI의 자기 설명이고, 현재 코드는 최신 도구 버전(Vite 8, Wrangler 4)으로 만들어졌는데 Genspark는 더 낮은 버전을 권장했다. 첫 배포에서 문제가 나올 수 있으므로 **9/24까지는 한 번 배포해 보는 것**을 권한다.
2. **오늘 작업분이 PC 한 대에만 있다.** GitHub에 올리기 전까지는 PC에 문제가 생기면 복구할 수 없다. 정합이 늦어지면 중간에라도 올리는 것을 권한다.
3. **팀원 결과물이 늦어지면** 정합·디자인 통일·배포가 연달아 밀린다. 9/23까지 받지 못하면 임시 이모지·임시 색으로 먼저 배포해 두고 나중에 교체하는 방법이 있다.
4. **배포 환경의 DB**는 비어 있는 상태로 시작한다. 발표 시연용 계정과 기록을 미리 만들어 둬야 한다.
