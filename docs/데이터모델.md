# 데이터 모델

- 최종 수정: 2026-09-21
- 서버 저장 방식이 아직 [미정]이므로 특정 제품에 묶이지 않는 관계형(표) 구조로 적는다. 방식이 정해지면 실제 SQL을 `migrations/`에 둔다.
- 원칙: **원본은 하나만 두고 여러 화면에서 조회한다.** 스터디 피드·개인 캘린더용 복사본을 만들지 않는다.

## 표 목록

### users — 사용자
| 컬럼 | 설명 |
|---|---|
| id | |
| login_id / password | 로그인 정보 (저장 방식에 따라 인증 서비스가 대신 관리) |
| nickname | 스터디에 표시되는 이름 |
| character_id | 가입 시 고른 캐릭터 |
| created_at | |

### subjects — 과목
| 컬럼 | 설명 |
|---|---|
| id, user_id | |
| name | 예: 수학 |
| color | 표시 색 |
| archived | 삭제 시 true (과거 기록 유지용) |

### study_sessions — 공부 기록 (타이머 1회 = 1건)
| 컬럼 | 설명 |
|---|---|
| id, user_id, subject_id | |
| status | running / paused / done |
| started_at | 시작 시각 |
| paused_at | 일시정지 중일 때만 값이 있음 |
| paused_total_sec | 일시정지 누적 초 |
| ended_at | 종료 시각 |
| duration_sec | 종료 시 확정: (ended_at − started_at) − paused_total_sec |
| memo | 공부 내용 |
| start_photo, end_photo | 오공시·오공완 사진 (선택) |

- 한 사용자에게 status가 running/paused인 기록은 **최대 1건**.
- 진행 중 경과 시간 = 현재 시각 − started_at − paused_total_sec (일시정지 중이면 paused_at 기준). 서버 시각을 쓰므로 새로고침에 영향받지 않는다.
- 날짜·주차 집계는 started_at의 한국시간 날짜 기준.

### xp_events — 경험치 내역
| 컬럼 | 설명 |
|---|---|
| id, user_id | |
| type | study_session / weekly_goal |
| ref_id | 근거가 된 기록·항목의 id |
| amount | |
| created_at | |

- (type, ref_id)는 한 번만 → 중복 지급 방지.
- 총 경험치 = amount 합계, 레벨은 총 경험치에서 계산한다(따로 저장하지 않음). 기록을 삭제하면 해당 내역도 삭제되어 자동으로 되돌려진다.

## 조회 규칙

| 화면 | 조회 방법 |
|---|---|
| 개인 누적·과목별 시간 | 내 study_sessions(done) 집계 |
| 스터디 피드 | 그 스터디 멤버들의 study_sessions·weekly_goal_items 조회 (복사 없음 → 여러 스터디에 가입해도 개인 누적이 중복되지 않음) |
| 개인 캘린더 | 내 events + 내가 가입한 스터디의 study_events |

## 접근 권한 (서버에서 검사)

| 자료 | 읽기 | 쓰기 |
|---|---|---|
| todos, events, subjects | 본인 | 본인 |
| study_sessions, weekly_goal_items, xp 합계 | 본인 + 같은 스터디 멤버 | 본인 |
| users의 닉네임·캐릭터 | 본인 + 같은 스터디 멤버 | 본인 |
| studies, study_members | 그 스터디 멤버 | 가입·탈퇴는 본인, 스터디 수정은 스터디장 |
| study_events | 그 스터디 멤버 | 스터디장 |
| 사진 파일 | 기록을 볼 수 있는 사람 | 본인 |
