## 4. 앱 기획

### 4-1. 방향 [확정]

- **심플하고 사용하기 쉽게.** 화면(UI)은 가볍게.
- 앱 안에 AI 기능은 넣지 않는다. 독립적인 관리 웹앱이다.
- **스터디 그룹의 취지:** 모여서 뭔가를 하는 공간이 아니라, 서로의 공부하는 모습·목표 달성하는 모습을 보면서 **의욕과 자극을 받는 공간.**
- 개인 페이지에서 한 활동이 스터디에 **자동으로 연동**된다. 스터디용으로 따로 입력하지 않는다.

### 4-2. 주요 기능 [확정]

| # | 기능 | 내용 |
|---|---|---|
| 1 | **공부기록 타이머** | 아래 4-3 참고 |
| 2 | **To-do 리스트** | 단순 체크리스트. 날짜·캘린더와 연결하지 않음 (복잡해지지 않게. 변경 시 재논의) |
| 3 | **개인 일정관리** | 개인 캘린더 (본인만 봄) |
| 4 | **주간 목표** | 개인 페이지에서 이번 주 목표를 쓰면 스터디에 자동 공유, 달성률 표시 |
| 5 | **스터디** | 멤버끼리 서로의 공부 기록·공부시간·목표 달성 현황을 보고, 기록에 **응원(👏)·댓글**을 남김. 모임 일정 기능은 넣지 않음 |
| 6 | **레벨업 시스템** | 가입할 때 캐릭터를 고르고, 공부하거나 목표를 완료하면 경험치 → 레벨업. 캐릭터가 크는 걸 보며 공부에 재미를 붙이게 하는 장치 |

### 4-3. 공부기록 타이머 흐름 [확정]

1. 내 **공부 종류(과목)** 를 미리 등록해 둔다 (예: 수학, 영어, 전공)
2. **"공부 시작"** 버튼 → 타이머 화면 + 아래에 내 과목 리스트
3. 과목 선택 → **시작** → 타이머가 돌아감. 버튼이 **일시정지 / 종료**로 바뀜
4. **일시정지** → 잠시 멈춤, 다시 누르면 이어서
5. **종료** → "오늘 무엇을 공부했는지" 쓰는 칸 → 저장하면 자동으로 기록
6. 과목별로 몇 시간 공부했는지, 무슨 내용을 했는지 조회

**규칙 [확정]**
- 일시정지한 시간은 공부시간에서 **뺀다**
- 새로고침하거나 브라우저를 닫았다 열어도 타이머가 **이어진다** (서버에 저장된 시작 시각 기준으로 계산)
- 타이머는 한 번에 **하나만**
- **한 번의 기록은 최대 8시간.** 넘으면 자동 종료되고, 더 공부할 때는 한 번 끊고 점검한 뒤 다시 켜도록 안내
- **회고는 4칸**(공부한 내용 / 성과 / 어려웠던 점 / 비고), 전부 선택. 스터디에는 "공부한 내용"만 공유
- **오공시·오공완 사진**은 타이머 시작/종료 때 **선택 사항**으로 첨부 (안 올려도 됨)

### 4-4. 누구에게 보이나

| 자료 | 나 | 같은 스터디 멤버 |
|---|---|---|
| 공부 기록 (과목, 시간, 내용, 사진) | O | O [확정] |
| 주간 목표·달성률 | O | O [확정] |
| 캐릭터·레벨·닉네임 | O | O [제안] |
| To-do | O | X |
| 개인 일정 | O | X [확정] |
| 응원·댓글 | O | 그 스터디 멤버만 O [확정] |

- 한 사람이 여러 스터디에 동시 가입 가능 [확정]

### 4-5. 아직 안 정한 것 → 기획하면서 정해 올 것

| 항목 | 현재 상태 |
|---|---|
| 여러 스터디에 가입했을 때 기록 공유 범위 | [제안] 가입한 모든 스터디에 자동 공유 (가장 단순) |
| 주간 목표 형식 | [제안] 체크리스트, 달성률 = 완료 항목 비율 자동 계산 |
| 경험치 규칙 | [제안] 공부 1분 = 1 XP (기록 1건당 최대 240), 주간 목표 항목 완료 = 30 XP, To-do는 경험치 없음 |
| 레벨 곡선 | [제안] 다음 레벨까지 100 × 현재 레벨 (10시간 공부 ≈ Lv4) |
| 캐릭터 | [확정 9/26] 팀원 1 그림 4종(리트리버·삼색냥이·검정냥이·달마시안). 레벨별 모습 변화는 리트리버만 3단계(Lv1~4 / 5~9 / 10+) |
| 스터디 가입 방식 | [제안] 초대 코드 입력 |
| 화면 디자인 | [확정 9/26] 크림 배경·먹색 글자·황금색 포인트, 서체 IBM Plex Sans KR, 하단 탭 5개 |
| 하지 않기로 한 것 | 앱 내부 AI, To-do↔캘린더 연동, **스터디 모임 일정**, 알림, 채팅, 랭킹 |

### 기획 공통 양식

맡은 기능마다 아래 네 가지만 적어 오면 합치기 쉽습니다.

1. 이 화면에서 **사용자가 하는 행동** (누르는 버튼, 입력하는 것)
2. 화면에 **보이는 정보**
3. **스터디 멤버에게 보이는 것 / 나만 보는 것**
4. **꼭 필요한 것 / 있으면 좋은 것** (마감이 6일 남아 우선순위가 필요)

- 화면 스케치는 손그림·태블릿 그림 사진이면 충분합니다.
- 작성한 내용은 노션 "아이디어 · 자료 모음" 또는 "회의록"에 올려 주세요.

### 어디에 무엇을 두나 [확정]

| 도구 | 용도 |
|---|---|

### 지켜야 할 것

- **코드는 노션에 복사해 붙이지 않습니다.** 코드는 GitHub에서만 주고받습니다.
- 설계 문서의 원본은 GitHub `docs/`입니다. 노션에는 링크만 겁니다 (같은 내용을 두 군데 쓰면 서로 달라집니다).
- **비밀번호·API 키·비밀값은 노션, GitHub, 단체 채팅 어디에도 적지 않습니다.** 저장소가 공개라서 올리는 순간 누구나 볼 수 있습니다.
- 작업 순서: **기획(docs) → 목업 → 구현 → 배포.** 앞 단계가 합의되기 전에 다음 단계를 먼저 만들지 않습니다.

### 저장소 폴더 구조

| 폴더 | 내용 |
|---|---|
| `docs/` | 기획·설계 문서 |
| `mockup/` | 화면 목업 (HTML) |
| 앱 코드 | 서버 진입점 `src/index.tsx`, 화면용 파일 `public/static/` |

- 앱 코드는 Genspark 권장에 따라 **저장소 루트**에 둡니다. [확정]

## 7. 기술 결정

### 기술 스택 [확정]

- 화면: HTML + CSS + JavaScript
- 서버: **Hono (TypeScript)**
- 배포: **Cloudflare Pages** (Genspark 호스팅이 사용하는 방식)
- 처음에는 "파이썬만 사용"이었으나, Genspark 호스팅이 파이썬 서버를 지원하지 않아 변경했습니다.

### 운영 측 확인 받은 것 [확정]

- 코드를 Claude로 작성해도 됩니다.
- 앱에 AI 기능이 꼭 들어가야 하는 것은 아닙니다 (독립 관리 웹앱으로 진행).

### Genspark에 직접 물어본 결과 (9/21)

> Genspark AI의 자기 설명이라, 시험 배포로 검증하기 전까지는 "유력한 정보"입니다.

| 항목 | 답변 |
|---|---|
| 배포 | **Genspark 호스팅**은 Genspark 계정만으로 가능 (Cloudflare 계정 불필요). 주소는 `https://<프로젝트명>.pages.dev` |
| 데이터 저장 | **Cloudflare D1** (데이터베이스) 지원 |
| 사진 저장 | **Cloudflare R2** 지원. 무료 한도·결제수단 요건은 "확실하지 않음" |
| 로그인 | 내장 기능 없음 → **직접 구현** |
| 코드 넘기기 | GitHub 저장소를 가져와 수정·배포 가능. 앱 코드는 **저장소 루트** 권장 |
| 재배포 | 코드만 고쳐 다시 배포하면 저장된 데이터는 유지 |
| 금지 | 설정에 KV, 크론(triggers)을 넣으면 배포 실패 (우리 앱엔 불필요) |
| 크레딧 | 수치 "확실하지 않음" |

### 서버 저장 방식 [뼈대에 적용]

- **D1(데이터) + 직접 구현 로그인 + R2(사진), Genspark 호스팅으로 배포**
- 이유: 추가 계정·외부 키가 필요 없고, 코드와 DB 구조가 저장소 하나에 모여 Genspark가 마무리하기 쉽고, 넘기기 전에 팀장 PC에서 미리 테스트할 수 있음
- 사진 저장(R2)이 막히면: 사진을 작게 줄여 D1에 저장하거나 사진 기능 우선순위를 낮춤 (사진은 선택 기능이라 핵심 흐름엔 영향 없음)
- 대안: Supabase(외부 서비스)
